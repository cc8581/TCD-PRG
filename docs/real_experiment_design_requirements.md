# TCD-PRG 真实实验平台设计准则与目标

> 历史设计基线：2026-09-18 起，运行模式、决策分支与动作步骤以 [`real_experiment_workflow_v2.md`](real_experiment_workflow_v2.md) 为准。本文中 PICK_REMOVE、压覆物体抓取、PyBullet PUSH 筛选和自动实机发送路径不再适用于当前平台；其余模型协议与安全约束仍需遵守。

状态：已确认的设计基线
适用范围：`real_experiment_app` 的后续架构、UI、推理、仿真与实机执行设计
记录日期：2026-09-15

## 1. 文档地位

本文档汇总本轮需求澄清中已经确认的决定。后续设计和实现必须以本文档为准；如需改变已确认行为，应先更新本文档并记录原因，不能在实现中静默改变语义。

本文档只约束真实实验平台的运行流程。真实平台“不限制准备动作总数”的决定，不追溯修改现有训练数据、Stage-C 标签、训练损失或历史 `H=5` 训练协议。

## 2. 总体目标

真实实验平台需要支持两种运行方式：

1. 自动模式：目标确定后自动完成感知、抓取判断、压覆物处理、PUSH 生成与评估、PyBullet 筛选以及实机动作发送。
2. 手动模式：操作者按阶段逐步触发，每一步都在 UI 中实时更新状态和可视化结果。

完整闭环为：

```text
加载或采集点云
  -> 多相机融合与正式预处理
  -> 实例感知与目标高亮
  -> 目标物抓取候选 Top-N + 最终位姿碰撞检查
  -> 有可行抓取：执行 TASK_GRASP
  -> 无可行抓取：推断压覆目标物的最上层物体
      -> 遮挡物抓取候选 Top-N + 最终位姿碰撞检查
      -> 有可行抓取：执行 PICK_REMOVE
      -> 无可行抓取：规则生成 PUSH 候选
          -> Push Evaluator 评分排序
          -> 分批扩展 Top-K 并行 PyBullet 仿真
          -> 选择对目标改善最大的有效 PUSH
          -> 执行 PUSH
  -> PICK_REMOVE/PUSH 后重新采集、感知并从头判断目标是否可抓
```

## 3. 点云输入与预处理

- UI 首先显示的“原始场景”是多相机融合并完成正式预处理后的点云，不显示单相机原始深度反投影结果。
- 感知、抓取和 Push Evaluator 必须分别遵循各自训练时的数据协议，不能为三个阶段强行统一点数。
- 感知与抓取使用其训练配置规定的确定性网格采样及点数协议。
- Push Evaluator 严格读取检查点中记录的 compiled PyTorch3D FPS 协议和点数。
- 点数不足时不得复制点或伪造有效掩码；按模型已有稀疏输入规则处理，无法满足协议时明确报错。
- 上一条约束适用于场景观测及模型有效点掩码，不改变冻结 GraspNet 适配器既有的固定长度内部采样协议。其目标裁剪只需满足配置中的 `target_min_crop_points`；不足 20,000 个不同目标点时，适配器按既有逻辑重复有效点的索引以形成固定长度输入，不能因此拒绝整个合法场景。此澄清修正了部署端额外拒绝稀疏目标点所导致的真实平台回归。
- 推理输入的点数与相应模型训练协议一致，不得为了 UI 或性能静默减少模型输入。

## 4. UI 与可视化

- 真实平台 UI 使用 GPU/OpenGL 点云渲染组件，替换当前 Matplotlib 3D CPU 重绘视窗。
- 显示层默认展示全部预处理点云；仅当点数超过 300,000 时，允许只对显示层下采样。
- 显示层采样必须与模型输入完全隔离，不能改变推理结果。
- 感知完成后高亮目标实例。
- 抓取阶段把候选抓取位姿渲染在点云中，并突出最终选中的位姿。
- PUSH 阶段把候选接触点、方向和固定行程渲染在点云中。
- 被推动物体也要高亮，且颜色必须与目标物体不同。
- 自动模式需要实时更新每个阶段的进度和结果，而不是只在流程结束后显示最终图。
- 手动模式按钮阶段为：

```text
加载/采集点云 -> 感知 -> 选择目标 -> 目标抓取与碰撞检查
-> 压覆物体推断 -> 遮挡物抓取与碰撞检查
-> PUSH 生成与评分 -> PyBullet 仿真 -> 发送动作
```

- 与当前决策无关的阶段自动跳过。

## 5. 目标选择与任务语义

- 任务开始时支持操作者指定目标，也支持随机选择一个可见实例。
- 随机模式使用感知预测的类别，并从该类别允许的功能区集合中随机选择功能区。
- 随机选择不要求固定随机种子或可复现。
- PICK_REMOVE 或 PUSH 后，继续使用平台现有的三维位置与外观特征追踪原物理目标。
- 目标丢失或身份不确定时停止自动流程并要求人工处理。

## 6. 抓取候选与碰撞检查

- 目标抓取与遮挡物抓取共用一个由当前配置提供的置信度阈值；不从检查点自动读取阈值。
- 抓取候选 Top-N 由 UI 配置，默认 `N=36`。
- 候选按模型分数从高到低检查。
- 如果多个候选通过碰撞检查，选择模型分数最高的无碰撞候选。
- 只检查最终抓取位姿，不检查预抓取、接近、闭合或抬升路径。
- 夹爪按候选的 `grasp_width_m` 设置开口宽度。
- 允许手指与目标物体接触。
- 夹爪其他部分与桌面或任意非目标物体接触时，该候选无效。
- 桌面和所有预测实例都参与碰撞检查。
- 场景实例使用由实例点云生成的多个凸体近似碰撞体；抓取碰撞检查与 PUSH 仿真共用同一场景几何。

## 7. 压覆关系与 PICK_REMOVE

- 当前感知模型不直接输出“压覆目标物的最上层物体”，也没有显式压覆关系预测头。
- 平台必须根据实例点云实时建立几何压覆关系图：
  - 查找与目标在 XY 平面重叠或紧邻的实例；
  - 使用点云高度分布判断其是否位于目标上方；
  - 沿压覆关系图向上搜索；
  - 选择最上层、最可能解除目标压覆的实例。
- XY 邻近、重叠比例和上下层高度差等阈值均需要在 UI 中配置。
- 默认规则应随实例包围盒和点云尺度自适应，而不是只使用固定距离。
- 对选中的最上层实例执行与目标抓取相同的 Top-N 预测和最终位姿碰撞检查。
- 如果存在可行抓取，执行 `PICK_REMOVE`，将其放入配置的移除区域。
- PICK_REMOVE 后重新采集、感知并从头判断目标是否可抓。
- 如果该物体没有可行抓取，进入 PUSH 分支。

## 8. PUSH 规则生成与模型评分

- PUSH 候选继续采用现有规则生成，不训练 PUSH 生成器。
- 在待推动实例的可见边界生成接触点。
- 推动方向限制在桌面 XY 平面。
- 推动距离固定为 `0.15 m`，不把距离扩展为多个候选值。
- Push Evaluator 只负责对规则候选进行改善概率评分与排序。
- 初始仿真候选数 Top-K 由 UI 配置，默认 `K=5`。
- 如果当前批次没有有效动作，按 `Top-5 -> Top-10 -> Top-15 -> ...` 扩展；每次新增下一批尚未仿真的候选。
- 直到找到有效候选或所有规则候选均已完成仿真。
- 所有候选均无效时停止自动流程，并在 UI 中提示人工处理。

## 9. PyBullet 场景几何

- 数据集回放可以利用数据集中可用的物体信息，但实机流程不能依赖类别对应 CAD 模型。
- 原因是标准 CAD 与真实物体可能存在明显几何差异。
- 实机场景中的每个预测实例由其点云生成多个凸体的近似凸分解碰撞体。
- 质量、物体摩擦系数、桌面摩擦系数、恢复系数等物理参数采用合理现实默认值，并全部在 UI 中可配置。
- 初始建议值可作为实现起点，而非最终标定值：
  - 物体质量：`0.20 kg`
  - 物体摩擦系数：`0.50`
  - 桌面摩擦系数：`0.60`
  - 恢复系数：`0.05`
- 实际默认值应通过后续真实实验调整。

## 10. PUSH 仿真执行器

- 使用项目已有 AG-160-95 模型，不使用简化方盒代替真实末端几何。
- 资源位于 `assets/robots/FR5_AG-160-95`：
  - 组合 URDF：`urdf/fr5_ag160_95.urdf`
  - 夹爪碰撞网格：`meshes/ag16095/kinematic/collision`
  - PyBullet 帮助代码：`tools/pybullet_model.py`
- PUSH 仿真只加载 AG-160-95 闭合状态的碰撞几何，忽略 FR5 整条机械臂碰撞。
- 夹爪闭合状态使用模型定义的 `closure=1.0`，对应受控关节约 `0.93 rad`。
- 夹爪作为运动学推动器，不模拟机械臂动力学。
- 只模拟从接触点开始的 `0.15 m` 推动行程，不模拟接近接触点的路径。
- 初始接触姿态仍需避免闭合夹爪与桌面或非推动物体发生初始穿透。
- 固定物理推动速度默认 `0.10 m/s`，并允许在 UI 中调整。
- 仿真关闭实时同步，在后台尽可能快地计算；物理时间步仍应对应配置的推动速度。
- 每个候选必须从完全相同的初始场景状态独立仿真。
- 候选仿真并行执行以缩短等待时间。
- 并行进程数由 UI 配置，默认 `min(CPU 逻辑核心数的一半, 8)`。

## 11. PyBullet 有效性与最终选择

一个 PUSH 候选的任务有效性同时满足：

1. 仿真后，被推动物体与目标物体在桌面 XY 平面的最小间距增大；
2. 被推动物体实际位移在计划推动方向上的投影大于 `0.01 m`。

补充规则：

- PUSH 撞动其他物体不影响任务有效性。
- 被推动物体离开工作区、掉下桌面或倾倒，也不影响 PyBullet 的“任务改善”判定，只要满足上述远离目标条件。
- 多个候选有效时，选择仿真后“与目标物体间距增量最大”的动作；不再以 Push Evaluator 分数作为有效候选之间的最终排序依据。
- Push Evaluator 分数用于决定优先仿真的候选批次。

## 12. 任务有效性与真实执行安全分层

- PyBullet 候选筛选只判断任务有效性。
- 真正向 FR5 发送动作前，必须保留平台现有的工作空间、逆解、急停和控制器安全检查。
- 不能因为 PyBullet 判断任务有效，就绕过真实执行边界的安全限制。
- 本阶段不新增“物体可能掉落/出界”的仿真安全否决规则。

## 13. 自动模式与设备行为

- 自动模式包含自动向机械臂发送动作。
- 选择自动模式并启动任务后，不再要求额外开启一次“自动执行”开关。
- 机械臂已连接但未使能时，平台自动使能 FR5。
- 设备已连接时不重复提示。
- 机械臂未连接时只提示一次，但不阻断感知、候选生成、仿真和最终动作选择。
- 未连接时把最终动作标记为“仅预测完成”，不发送动作，并允许加载另一个场景继续测试。
- 实机动作仍需通过第 12 节规定的执行边界检查。

## 14. 闭环终止条件

- 不设置固定准备动作总数上限。
- 这替代真实平台运行时原先固定 `H=5` 的终止方式，但不修改历史训练协议。
- 为防止模型误差造成无限循环，满足任一条件时自动停止：
  - 目标抓取成功；
  - 所有 PUSH 候选均无法产生有效改善；
  - 目标丢失或身份不确定；
  - 连续两次重新感知后场景变化低于配置阈值；
  - 同一物体被连续选择执行相近动作；
  - 操作者点击停止；
  - 设备或控制器报错。
- 停止后在 UI 中给出明确原因并转人工处理。

## 15. 配置持久化

以下参数至少需要在 UI 中配置并持久化：

- 自动/手动模式；
- 指定/随机目标模式；
- 抓取 Top-N，默认 36；
- PUSH Top-K，默认 5；
- 抓取共用置信度阈值；
- 压覆关系的自适应规则参数；
- 实例凸分解参数；
- 物体质量、摩擦系数、桌面摩擦系数和恢复系数；
- PUSH 物理速度，默认 `0.10 m/s`；
- PyBullet 并行进程数；
- 场景变化与重复动作停止阈值。

配置保存后必须写入平台配置文件；下次启动自动加载上次保存的值，不要求操作者重新设置。

## 16. 耗时统计

UI 需要分别统计并显示：

- 点云预处理；
- 感知推理；
- 目标抓取预测；
- 目标抓取碰撞检查；
- 压覆关系推断；
- 遮挡物抓取预测；
- 遮挡物抓取碰撞检查；
- PUSH 规则生成；
- Push Evaluator 评分；
- 每个 PyBullet 候选仿真；
- PyBullet 总耗时；
- 最终动作决策；
- 端到端总耗时。

当前不要求每次推理自动保存完整实验记录、全部中间点云、配置快照或 UI 截图。耗时和阶段结果首先服务于 UI 在线检查。

## 17. 当前检查点选择基线

真实平台当前选择 60,000-step `model_last.pt` 作为 Push Evaluator 权重。它与 step-18,000 `model.pt` 在同一 250 场景、115,628 动作完整验证协议下比较后，主要排序指标更好：

| 指标 | step 18,000 | step 60,000 |
|---|---:|---:|
| AUROC | 64.67% | 71.89% |
| AUPRC | 12.65% | 17.59% |
| Top-1 improvement | 49.18% | 53.11% |
| Top-3 contains improvement | 70.02% | 73.64% |
| F1 | 19.61% | 25.32% |
| 无权重 BCE | 0.7377 | 0.7621 |

虽然 step 60,000 的 BCE 略差，但动作排序和区分指标一致改善，因此用于当前真实平台设计基线。

## 18. 验收目标

后续实现至少满足以下验收条件：

1. 自动和手动两种模式均能在无机械臂连接时完成完整“仅预测”流程。
2. UI 按阶段展示点云、目标、抓取候选、待推动物体、PUSH 候选、模型分数和仿真结果。
3. OpenGL 点云视窗在显示不超过 300,000 点时交互流畅，且不改变模型输入。
4. 抓取 Top-36、PUSH Top-5 和所有新增物理/关系参数可配置并持久化。
5. 抓取碰撞检查严格执行本文第 6 节语义。
6. 压覆关系选择能够从目标沿几何关系图找到最上层待处理物体。
7. Push Evaluator 只排序规则候选；PyBullet 从独立初态并行验证候选。
8. Top-K 能按 5 的增量扩展到全部候选。
9. 最终 PUSH 按最大间距增量选择，并满足方向投影位移大于 0.01 m。
10. 实机执行不绕过现有工作空间、逆解、急停和控制器检查。
11. 无固定动作总数上限，但所有防循环终止条件可验证。
12. UI 显示完整分阶段与端到端耗时。

## 附录 A：问答决策索引

1. 原始显示点云：多相机融合并完成预处理后的点云。
2. 流程控制：同时支持全自动与逐阶段手动执行。
3. 抓取成功：从高分候选中进行碰撞检查，碰撞包括桌面。
4. 抓取候选数：UI 可配置，默认 36；PUSH Top-K 默认 5。
5. 多个可行抓取：选择模型分数最高者。
6. 动作分支：保留 PICK_REMOVE，不简化为只有目标抓取和 PUSH。
7. 待处理物体：主观目标是压覆目标物的最上层物体；模型不直接输出，需要实时几何推断。
8. 压覆推断：接受 XY 重叠/邻近、Z 位于上方并沿图搜索最上层实例。
9. 遮挡物可抓：执行 PICK_REMOVE，重新观测；不可抓则进入 PUSH，PUSH 后也重新观测。
10. PUSH 生成：沿可见边界生成接触点和桌面 XY 方向，距离固定 0.15 m。
11. PyBullet 目标：判断推动是否改善目标，而非仅做一般安全过滤。
12. 有效 PUSH：目标间距增大，且沿计划方向实际位移投影超过 0.01 m。
13. 多个有效 PUSH：选择间距增量最大者。
14. 当前 Top-K 全部无效：扩大候选数量继续仿真。
15. 扩展方式：Top-5、Top-10、Top-15，依次增加。
16. 全部候选无效：停止自动流程并提示人工处理。
17. 实机场景：不能按类别匹配 CAD 模型。
18. 实机碰撞体：接受由实例点云构建近似碰撞体。
19. 碰撞体形式：使用多个凸体的近似凸分解。
20. 物理参数：统一现实默认值，质量和摩擦等允许 UI 配置。
21. 暂无实测默认值：先按现实合理值设置，后续调整。
22. 抓取碰撞：检查桌面和所有其他预测物体。
23. 抓取碰撞范围：只检查最终抓取位姿，不检查完整路径。
24. 点云视窗：允许替换为 GPU/OpenGL 渲染。
25. 显示点数：默认全部显示，超过 300,000 才对显示层下采样。
26. 模型点数：三个阶段分别严格遵循各自训练协议。
27. 末端工具：项目中已有夹爪模型，PUSH 使用闭合夹爪。
28. PUSH 工具模型：只加载闭合 AG-160-95，忽略整条 FR5 碰撞。
29. 候选仿真：每个候选从完全相同的初始状态独立仿真。
30. 仿真目标：需要快速完成，用于真实动作前的可行性验证。
31. 时间执行：不做实时同步，后台快速仿真，使用固定物理速度。
32. PUSH 速度：默认 0.10 m/s。
33. PUSH 路径：只模拟从接触点开始的 0.15 m 行程。
34. 撞动其他物体：候选仍可判为任务有效。
35. 推出工作区/掉落/倾倒：只要远离目标，PyBullet 任务判定仍可有效。
36. 有效与安全分层：PyBullet 只判任务改善；真实执行另行把关。
37. 实机边界：保留工作空间、逆解、急停和控制器安全检查。
38. 自动模式：包含自动向机械臂发送动作。
39. 未连接机械臂：标记“仅预测完成”，允许继续测试其他场景。
40. 已连接设备：不重复提示；未连接只提示一次。
41. 自动启动：选择自动模式并启动任务后，无额外自动执行开关。
42. 已连接但未使能：自动使能 FR5。
43. 压覆关系阈值：全部做成 UI 可配置参数。
44. 压覆默认规则：接受随物体尺度自适应。
45. 耗时：统计所有主要阶段、每个候选仿真和端到端时间。
46. 自动归档：不要求每次保存完整实验记录和截图。
47. 抓取夹爪状态：按预测宽度设置，允许与目标接触，其他碰撞淘汰。
48. 抓取场景几何：与 PUSH 共用实例点云凸分解碰撞体。
49. 目标选择：既支持操作者指定，也支持随机目标。
50. 随机功能区：从预测类别允许的功能区中随机选择。
51. 随机选择：不要求可复现。
52. 抓取阈值：目标与遮挡物抓取共用同一阈值。
53. 阈值来源：只使用当前配置；所有配置保存后下次自动加载。
54. PyBullet 候选：并行仿真，等待时间越短越好。
55. 并行数：UI 可配置，默认 `min(逻辑核心数/2, 8)`。
56. 手动模式：按九个阶段拆分，不适用阶段自动跳过。
57. 重观测：继续使用三维位置和外观特征追踪原目标。
58. 准备动作：不设置固定总数上限。
59. 防循环：采用目标成功、无有效 PUSH、目标丢失、场景无变化、重复相近动作、人工停止和设备错误等停止条件。
